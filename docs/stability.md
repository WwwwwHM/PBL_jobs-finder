# 故障恢复与重试边界

## Redis

启用 `STATE_BACKEND=redis` 后，验证码、Token、每日配额共用 `REDIS_URL` 和 `REDIS_PREFIX`。不可用时明确失败，禁止自动回退内存。验证码 300 秒、发送冷却 60 秒、错误最多 5 次、原子单次消费；Token 604800 秒，复用不续期，退出双向撤销。每日配额按 `APP_TIMEZONE` 的日期分键并保留 48 小时，并发使用 Lua 原子占用；失败按原始日期退款，不影响次日配额。

真实重启测试使用独立 Redis 端口和目录、AOF `appendfsync always`，杀死进程再启动，校验验证码、Token、配额；另启动两个新 Python 进程验证配置接入。部署 Compose 选择 `appendfsync everysec`，突然断电可能丢失最近约一秒写入；测试 always 的结果不能当作 everysec 零丢失保证。

退款时 Redis 也不可用：保留原始业务异常，记录 `quota.refund` 错误编号。当前没有持久化自动退款补偿，可能暂占一次配额，跨日自然隔离；管理员应核对日志和业务记录后处理。内存模式只用于单进程演示，重启丢失 Token、验证码、配额，且没有 Redis 模式完整的发送冷却和错误计数保护。

## 模型与 Embedding

两类客户端的最大重试数配置均允许 0–5，默认 2，即最多尝试 3 次。聊天客户端关闭 SDK 内部重试，由本地代码统一控制；每次调用结束关闭连接资源。

| 错误 | 行为 |
| --- | --- |
| 聊天超时、网络连接失败、HTTP 408/429/500/502/503/504 | 有上限重试，退避为 0.25、0.5 秒（默认值） |
| 聊天鉴权失败、无效请求、空结果、非法 JSON/Schema | 不作传输层重试；返回可理解错误，允许用户修正后再试 |
| Embedding 超时、连接失败、HTTP 408/429/5xx | 同样有上限重试 |
| Embedding 鉴权、非法 URL、TLS 配置错误、非法向量（含 NaN/Infinity） | 不盲目重试；保留错误编号与堆栈位置 |

默认每次网络超时参数 30 秒、两次退避合计 0.75 秒，按每次 30 秒估算，一个远程调用的重试预算约 **90.75 秒**。HTTP 客户端的 timeout 是连接/读写阶段等待限制，**不是整个用户操作的硬性墙钟截止时间**；DNS、分阶段等待、慢速持续响应、队列、OCR、渲染、数据库锁和多次模型调用会增加总耗时。Embedding 使用 requests，其连接/读取也可分别消耗 timeout。不可把 90.75 秒描述成整个页面操作的严格上界。

简历技能筛选可能额外调用一次模型；结构化简历生成的内容纠错也有自己的调用。面试首轮包括检索及生成，后续回答包括检索、评价和可能的最终报告。性能门槛是正常真实服务样本的 30 秒/15 秒目标，并非故障超时承诺。硬性任务截止、取消和后台工作队列属于后续优化。

## 业务恢复

- 解析、OCR、模型、Embedding、Chroma 或数据库失败：新建业务不保存半成品，配额按规则退还；表单保留可重试输入。
- 最后一题的报告失败：既有问答仍在库中，最后一次回答与报告原子提交；页面保留最后答案，重新提交不扣新建面试次数。
- PDF/Word 数据库保存失败：清理本次文件，保留上一份导出；修复故障后可以再生成。
- Redis 断连：`/health/live` 仍响应，`/health/ready` 返回 503，鉴权与配额明确失败；恢复后可继续使用原 Token。
- API 使用稳定错误码；系统异常附 `error_id`。页面也提供同类错误编号以便查日志。

## 日志与健康检查

异常链只记录类型、文件位置、行号及函数名，不记录第三方异常文本、SQL 参数、模型响应正文或 Pydantic 输入。业务错误只记录应用定义的安全消息；请求上下文仅记录长度、编号等元数据。HTTP、模型 SDK 和 SQLAlchemy engine 日志最低为 WARNING，避免应用 DEBUG 顺带输出请求正文。常见凭据、手机号、邮箱及 Redis URL 密码继续脱敏。

Mock 验证码投递仍有意写入服务器控制台；这是演示登录机制，不是真实短信，也不能对外开放服务器日志。

`/health/ready` 仅探测 SQLite 和配置的 Redis，不调用付费模型、不证明 Embedding、Chroma 题库或 Chromium 就绪。`/health/live` 仅证明进程可响应。完整依赖检查需运行部署预检和业务验收脚本。
