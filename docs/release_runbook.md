# 发布、恢复与最终演示

## 发布材料与版本

发布单位为 Git 提交对应的源码、`uv.lock`、经安全渠道保存的部署配置及同一停写点的数据快照。安装与启动命令见 [部署说明](../部署说明.md)，接口合同见 [api.md](api.md)，实际证据见 [工程验收](engineering_acceptance.md)。代码的提交号用 `git log -1 --format=%H` 获取；最终验收记录通过对应文档提交的父提交定位代码版本，避免把本地未提交题库资料误纳入版本。

## 停写快照与回滚

1. 将入口切入维护状态，等待在途诊断、导出、答题和题库导入完成；停止应用及所有独立写入进程。快照期间不允许新写入，也不允许自动重启应用。
2. 正常关闭专用 Redis，等待退出；保存完整持久化目录，涵盖 RDB、AOF 及 Redis 7 的 AOF manifest / appendonlydir。不得只备份部分键后与完整 SQLite 混用。共享 Redis 需要单独设计租户恢复，当前手册针对专用实例。
3. 在新的快照目录成组保存 SQLite 及存在的 WAL/SHM、完整 Chroma 目录、导出目录，若路径有自定义则逐一登记。停写期间可用 SQLite backup API 生成合并后的独立数据库；严禁仅复制运行中的主数据库文件。日志和上传缓存单独保留用于排障，不是恢复业务事实的依据。
4. 保存代码提交号、配置副本、模型/Embedding 型号与维度、Redis 版本及持久化模式、快照时间、文件校验值。凭据及快照仅存储在受控位置，不提交 Git。
5. 回滚时保持入口关闭，把全部快照恢复到**新目录或新卷**，检验文件校验值。保留失败版本数据以便排障。检出匹配快照的代码到另一发布目录，重新按对应锁文件安装；将路径、Redis URL/前缀和 Embedding 配置切换到恢复副本。
6. 先启动恢复的 Redis，再启动单 worker 应用。执行发布预检、HTTP 健康检查、历史摘要及详情比较、受权 PDF 下载比较、题库数量与 top 5 检索、登录态与当日配额核对。
7. 确认无误后恢复入口。到期 Token、验证码和跨日配额按实际时间失效，恢复不得人为延长 TTL；到期导出仍需重新生成。生产回滚还应决定是否统一撤销快照中的登录态，避免复活快照后曾撤销的 Token。

这是维护窗口中的一致性恢复，不提供在线分布式快照或跨版本降级迁移。快照后的业务写入会被回滚，应按业务需求选择快照时间并保留审计。本轮自动化演练使用同一候选代码和合成数据，证明四类存储协调恢复；没有声称任意旧版本可以读取当前新结构。

## 可重复自动演练

```powershell
.\.venv\Scripts\python.exe -m scripts.check_browser_flow --rollback --output tmp/rollback-fixed-new
.\.venv\Scripts\python.exe -m scripts.check_browser_flow --live --rollback --output tmp/rollback-live-new
```

固定模式仍启动真实 Chromium、FastAPI/Gradio、SQLite、Redis 和 Chroma，只替换模型与 Embedding；真实模式复制配置中的题库到隔离目录并调用模型。进行真实模式演练前不要同时写入源题库；一体化干净部署脚本使用刚初始化且无其他写入者的题库。

演练先经浏览器登录、诊断、下载 PDF、回答 5 题并保存报告；重启应用验证持久化，再停止写入者做快照。随后实际修改 SQLite 分数和面试状态、删除导出 PDF 和一条向量题、撤销 Token 并增加配额；正常关闭 Redis，恢复四类存储到新路径。恢复后比较历史详情、PDF 字节、全部题库内容/元数据/向量摘要、top 5 查询、登录和配额，最后验证退出后访问拒绝。快照文件先逐文件校验，再启动恢复进程，防止启动时幂等初始化掩盖缺失数据。

## 人工最终演示（约 5–8 分钟）

使用专用演示账号和合成简历，不在屏幕上显示真实用户资料或服务密钥。

1. 打开首页，展示 `/health/live` 和 `/health/ready` 正常。输入演示手机号，通过服务端控制台 Mock 验证码登录，记录剩余配额。
2. 上传文本 PDF 或粘贴合成简历，填目标岗位，运行诊断；展示匹配分、缺失关键词、建议和 STAR 改写，核对配额只减少 1。
3. 补充一段真实来源的示例履历或直接生成，下载 PDF，打开检查中文、分页、联系方式和照片（素材包含时）。说明下载需登录且有效期 24 小时。
4. 使用入门难度完成默认 5 道主问题，展示每轮反馈和最终逻辑/专业/表达报告；本会话总计扣 1 次。
5. 打开“我的记录”，展示两类摘要、优化稿和完整问答；刷新页面验证登录恢复，重启应用后再次验证历史及配额（须使用 Redis）。
6. 退出，确认登录页恢复、旧 Token 历史请求和旧下载被拒绝。说明当前短信为 Mock、仅单 worker、模型延迟和未验证部署范围。

界面截图只能证明自动化时的状态；人工演示与用户主观体验验看应由展示者实际操作确认。

## 已知限制与后续顺序

1. 公网开放前补齐真实短信、统一登录防滥用、HTTPS 和代理信任配置；当前发布为本地演示交付。
2. Redis 退款断连尚无持久化补偿；下一步设计退款事件及幂等恢复。内存模式重启丢失登录/配额。
3. 具备 Docker/服务器条件后完成镜像构建、Linux 字体与 OCR/PDF、卷权限、重启持久化及恢复验收；不将 Compose 草案当成已运行结果。
4. 当前 SQLite、面试锁和 Gradio 队列限定单实例单 worker。未来先量化写锁/并发瓶颈，再决定 PostgreSQL/MySQL、分布式锁及对象存储迁移。
5. 导出 24 小时到期；历史长期保存，旧缓存/备份需独立保留策略。后续补用户数据删除、备份轮换和大模块拆分。
