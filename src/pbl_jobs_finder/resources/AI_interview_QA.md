# AI大模型应用开发面试题库

## 1. 什么是AI Agent？ 它和直接调用大模型API有什么区别？

AI Agent是一个能感知环境、拆解任务、调用工具的自主系统，它用LLM作为大脑，各种工具作为四肢五官来完成用户交代的各种任务；而直接调用大模型API本质上是在跟LLM对话，只会一问一答，用户输入prompt，LLM吐出一段回答，其他的操作全靠用户自己完成。

本质上的差异是
1、AI Agent会用ReAct循环作为思考范式，通过“推理-调用-观察”作为一个循环周期不断循环思考直至解决问题；API调用LLM则是单链路的对话问答，不存在循环链路

2、AI Agent有记忆功能，能支持上下文对话，不需要每次输入历史对话；API调用LLM不包含记忆功能，每次对话都是新的记忆，需要把历史内容全部输入到提示词里

3、AI Agent能调用外部工具，能够通过调用工具来与外界互动、了解外界信息；API调用LLM则无法调用工具，只能输入输出文本信息，无法与外界互动

### 1.1 追问：ReAct 这个循环具体是怎么实现的？模型怎么知道什么时候该停下来？

实现上就是一个while循环，每一轮会把当前任务描述、历史对话记录、上一步工具调用返回结果拼接成prompt喂给模型。模型按照格式输出thought、Action、Action input三个字段，框架解析出来之后调用对应工具，工具返回的结果作为observation拼入prompt进入下一个循环。

停止条件一般有两种：一种是模型拿到observation后判断问题已经解决，输出final answer标记，表示任务完成了；另一种是循环次数超过上限，模型强行停止思考，LangChain默认上限为15轮。


### 1.2 追问：Agent现在最大的问题是什么？ 实际落地效果怎么样？

目前Agent最大的问题是不可控，模型推理能力不稳定，复杂问题拆解经常出错，工具调用的参数也可能瞎填，中间有一步跑偏后面就越走越偏。

实际落地不会纯靠Agent，而是人为设定好任务节点，拆解出各个小问题让Agent执行，属于是在自主性和可控性之间进行工程化平衡。目前claude code、codex等编程类Agent的落地成果案例较多，因为编程任务的逻辑性强，代码有明确的测试验收流程。

### 1.3 追问：Function Calling 和 Tool Calling 有什么区别？

严格来说没什么区别，最早openai把工具调用命名为Function Calling，后来2023年改名为Tool Calling，应该是想表达模型调用的不只是函数。实际底层都是模型输出一段结构化的JSON，包含需要调用什么工具、传什么参数，由应用层解析去执行然后再返回结果回来。

## 2. AI Agent的核心组件有哪些？感知、决策、执行、记忆各自的作用是什么？

一个完整的Agent通常由四个核心组件组成：感知、决策、执行、记忆。

感知组件的作用是让Agent能够接受和理解外部的信息，输入大多数是自然语言指令，但也可能有图片、文件内容、API返回的结构化数据等，这就要通过各种工具调用把多模态的输入解析成统一的结构化JSON给LLM读取。

决策组件就是LLM，是agent的大脑，利用LLM的推理能力理解当前任务，分析已有信息，做出下一步要做什么的自主决策。比如用户说“帮我分析这份消息报表。”，决策组件就会判断出：先读文件，再提取关键信息，分析信息，最后生成分析报告。整个任务的拆解和编排都靠它。

执行组件的作用是把决策转成实际行动。最典型的就是工具调用，解析LLM的输出并调用相关工具执行任务并返回工具调用结果供LLM进行下一步决策。比如跑代码、查数据库、调外部API、读写文件都是执行组件的活。

记忆组件的作用就是让agent能记住历史信息。短期记忆就是当前对话的上下文，记录本次任务已经做了什么、拿到了什么结果。长期记忆则是把重要信息持久化保存下了，下次会话还能用。没有记忆的Agent每一步都像失忆一样，效率很低。

### 2.1 追问：短期记忆塞满了怎么办？上下文窗口不够用的时候有什么解决方案？

常用的策略有三种。第一种是滑动窗口，只保留最近的N条信息，其余的全丢掉，这个方法简单粗暴但是会丢信息；第二种是摘要压缩，每隔一段让模型把会话压缩成一段摘要，用摘要替换掉原文。第三章是检索式记忆，把所有历史会话全部存入向量数据库中，每轮对话开始时根据当前问题检索最相关的几条历史塞进上下文。实际项目中一般摘要和检索配合使用，效果最好。

### 2.2 追问：如果决策模块选错了工具，或者工具调用失败了，Agent怎么处理？

好的Agent框架自带错误恢复机制。工具调用失败后执行模块会返回错误信息给决策模块，决策模块分析错误信息重新规划，可能换个工具或者更换参数重试。比如查数据库时SQL语法报错，LLM看到错误信息后修正错误再试一次。通常会有一个最大重试次数，一般设置3-5次，超过次数就更换别的方案。选错工具也类似。不过模型的纠错能力有限，复杂场景下还是需要依靠人工设置兜底逻辑。

### 2.3 追问：多个Agent协作的时候，它们的记忆是怎么共享的？

多个Agent记忆共享一般有两种模式。一种是共享黑板，所有Agent的记忆放到一个公共存储中共享读写，类似多人协作文档，比如CrewAI。另一种是消息传递，Agent之间通过结构化消息通信，每个Agent有自己独立的记忆空间，只有通过消息才能获取别人的信息，比如AutoGen，Agent之间的对话记录就是消息传递的载体。共享黑板简单但容易消息爆炸，消息传递隔离性好但是通信开销大，得根据实际场景选择。

## 3. 什么是AI Agent中的工具调用（Tool Calling）？ 它的基本流程是怎样的？

工具调用是Agent与外部世界交互的核心机制。就是让大模型在需要的时候，自己决定调用什么工具、传什么参数，然后根据工具返回的结果继续推理。这是Agent从“只能说”到“能做事”的关键能力。

基本流程分四步：

1）先告诉模型有什么工具可用，每个工具干什么、参数是什么格式，这些信息随Prompt一起发给模型。

2）模型在对话中判断当前情况需要用某个工具，输入结构化的JSON，里面包含工具名和参数值。但是模型自己不执行任何操作，它只说要用什么工具。

3）应用层接收并解析这段JSON，执行操作后返回结果给模型。比如调API、跑SQL、读文件。

4）模型拿到结果后要么返回答案，要么继续调用别的工具。

举个例子，用户问“帮我查一下苹果公司今日股价”。模型不会瞎编一个数字，而是生成一段调用股价查询API的请求，应用层执行这个API拿到真实数据，再把数据喂回给模型，模型用真实数据来回答。

### 3.1 追问：如果模型输出的工具调用参数格式不对，JSON解析失败了怎么办？

分两层处理，第一层是解析容错，设置宽松JSON解析器，能自动修复常见的JSON格式错误，比如少个逗号，缺个引号。LangChain里就有专门的OutputFixingParser来做这个事。

第二层是重试机制，把错误信息拼回prompt，告诉模型“你上次的JSON格式有错误，正确的格式是这样的”，让它重新生成，一般重试2-3次就能拿到正确格式。如果用原生Function Calling 而不是 Prompt 注入方式，格式出错的概率就低很多，因为模型会在训练的时候就学习过这个格式。

### 3.2 追问：模型怎么处理一个工具的输出特别长的情况？比如搜索返回了几万字的结果？

首先直接把几万字上下文塞入prompt肯定不行，既浪费token又容易干扰模型判断，常见的作法是做截断或者摘要。最简单的就是截取前N个字符，比如只取前2000字。更好的方式是先用一个快速模型做摘要提取信息，再把摘要喂给主模型。
